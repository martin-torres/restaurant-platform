## Architecture Decisions

- **Realtime channel**: Using existing `subscribeToOrders` (Supabase Realtime channel `orders-channel`) — all dashboards already subscribe, we just add notification callbacks inside the existing `onInsert`/`onUpdate` handlers
- **No polling**: Realtime push only — no setInterval fetching
- **OrderProvider lives in App.tsx** — wraps entire app so toasts appear on every surface
- **Pulse animations** trigger on `is_available`/`is_reserved` changes AND incoming order events, auto-clear after 1.5s
- **Toast deduplication** handled in `OrderToast.tsx` (by `notification.id`)
- **Persistence**: Notifications survive navigation via `localStorage`
